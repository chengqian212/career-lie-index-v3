# 职业身份风险识别系统 — 功能说明

> 本文档基于 v3 版本源码直接分析写成，描述系统实际具备的完整功能。
> 不依赖任何已有 Markdown 文档。

---

## 一、产品定位

本系统是一套**面向相亲交友场景的多 Agent 职业身份风险识别工具**。其核心假设是：在相亲交流中，对方关于职业、身份、经历的描述可能存在不实或夸大。系统通过多轮自然语言对话逐步收集信息，利用多个专业分析 Agent 协作判断对方回答的可信度，最终输出一个量化的"谎言指数"（LieIndex）及结构化的评估报告。

系统提供两种交互方式：
- **Web 界面**（Streamlit）：模拟聊天对话，带分析过程监控面板
- **命令行界面**（CLI）：终端逐轮交互，实时显示各节点执行情况

## 二、核心功能全景

### 2.1 多轮对话信息收集

系统设计为**8 轮**（可配置）的对话流程。每一轮的逻辑：

1. 系统根据当前掌握的信息和疑点生成一个追问
2. 用户输入（模拟）对方的回答
3. 系统对该轮回答进行多维度分析
4. 根据分析结果决定继续追问或终止对话生成报告

追问并非随机生成，而是由**策略监督器**（Strategy Supervisor）根据当前风险态势、未解决的异常类型，从 9 种专业追问策略中选择最合适的一种，再由**追问生成器**（Followup Generator）基于该策略方向生成自然、符合相亲语境的提问。

### 2.2 快速预分析（Quick Preanalysis）

每一轮用户回答进入系统后，首先经过快速预分析节点。它在**单次 LLM 调用**中同时完成以下三件事：

| 分析维度 | 输出 |
|----------|------|
| 事实抽取 | 从回答中提取职业身份、岗位、公司、工作内容、时间线等结构化事实 |
| 异常检测 | 识别语义不一致、逻辑矛盾、过度解释、回避回答、自我纠正等异常信号 |
| 风险标签 | 输出 severity（严重度：CRITICAL/HIGH/MEDIUM/LOW）和 confidence（置信度），以及 surface_risk_score（0-100）|

此外还产出：
- `specificity_level`：回答的具体程度（HIGH/MEDIUM/LOW）
- `experience_density`：经验密度（判断是泛泛而谈还是包含具体经历细节）
- `generic_answer_flag`：是否属于"正确但空洞"的常识层回答

### 2.3 按需专家路由（On-Demand Specialist Routing）

不同风险等级的回答触发不同分析深度：

| 风险等级 | surface_risk_score | 处理策略 |
|----------|-------------------|----------|
| 低风险 | < 30 | 跳过专家，直接风险聚合 |
| 中风险 | 30-50 | 调用 1 个核心专家 |
| 中高风险 | 50-70 | 调用多个相关专家 |
| 高风险 | ≥ 70 | 调用全部 4 个专家 |

路由决策由**轻量路由监督器**（Lightweight Routing Supervisor）做出，它综合规则判断（严重度、置信度、异常状态、事实数量）和 LLM 决策，决定调用哪些专家。

### 2.4 四维专家并行分析

当选中的专家被调用时，它们通过 LangGraph 的 **Fan-out 机制并行执行**，互不依赖。每位专家独立分析并产出一个包含 severity、confidence 的证据清单。

| 专家 | 分析维度 | 检测内容 |
|------|----------|----------|
| **Semantic Agent** 语义一致性专家 | 语义 | 职业身份、岗位、工作内容等表述在多轮对话中是否前后一致；确认回答具体程度；交叉验证不同描述是否冲突 |
| **Logical Agent** 逻辑时间线专家 | 逻辑 | 时间线索是否自洽（入职时间、跳槽时间、项目周期）；因果关系是否合理；职业路径是否符合逻辑（如从 A 岗位跳到 B 岗位的时间窗口是否合理） |
| **Domain Agent** 职业常识专家 | 领域知识 | 职业内容描述是否符合基本行业常识；岗位职责描述是否与该职位的普遍认知吻合；工作内容细节是否经得起常识检验 |
| **Psycho-Linguistic Agent** 心理语言学家 | 心理语言学 | 识别回避策略、过度解释、自我纠正、话题转移等"软信号"；分析回答中的不确定性和模糊表达；注意：该专家结果仅作为辅助信号，不单独构成高风险结论 |

### 2.5 风险聚合与 LieIndex 计算

**风险聚合器**（Risk Aggregator）将以下来源的风险证据汇总：

- 快速预分析的异常
- 经验密度分析
- 各专家的证据清单

每条证据独立计算风险值：
```
V_i = severity_base_score × confidence_weight
```
其中：
- severity_base_score: CRITICAL=45, HIGH=25, MEDIUM=10, LOW=3
- confidence_weight: CRITICAL=1.0, HIGH=0.8, MEDIUM=0.5, LOW=0.2

所有独立风险值通过**概率类独立事件叠加公式**合并为综合 **LieIndex**：
```
LieIndex = 100 × (1 - ∏(1 - V_i/100))
```
该公式确保：多个低风险叠加不会超过 100，但有足够灵敏度区分不同程度的风险。

### 2.6 策略监督与决策

**策略监督器**（Strategy Supervisor）是一个 LLM-as-Judge 节点。它在每轮分析后做出两个关键决策：

1. **继续还是结束**：根据当前风险指数、异常解决情况、对话轮次（最少 5 轮才能结束）综合判断
2. **选择追问策略**：如要继续，从 9 种追问策略中选择最适合当前情况的

策略分类体系：
- **低风险通用场景**（daily_routine, entry_experience, work_style, recent_memory）：自然的信息扩展
- **泛泛回答专用**（light_clarification）：温和澄清宽泛的职业描述
- **广泛探索策略**（experience_probe, knowledge_probe）：从经历和知识两个角度深入
- **经验链追问**（process_sequence, boundary_judgment, real_constraint, counterexample, term_clarification, output_evidence）：6 种深层追问角度，循环使用避免重复

### 2.7 追问生成

**追问生成器**（Followup Generator）将策略方向转化为自然对话。它遵循两个步骤：
1. **粗生成**：根据策略执行指引生成追问
2. **润色**（Polish）：将追问包装成符合相亲语境的自然表达，避免生硬的"审问感"

追问还会追踪目标异常，当对同一个异常的追问超过上限时自动停止，避免反复追问同一问题引起对方警觉。

### 2.8 记忆系统：事-异双表

系统维护两个核心数据结构在整个对话过程中持续更新：

**事实表（Facts Table）**
- 存储从对话中提取的所有客观事实
- 每条事实包含：轮次编号、内容、分类（职业身份/工作内容/时间经历等）、原文引用
- 支持按轮次和类别检索

**异常表（Anomalies Table）**
- 记录所有检测到的不一致、矛盾和可疑信号
- 每条异常包含：来源（quick_detection/semantic/logical/domain/psycho_linguistic）、类型、描述、严重度、置信度、状态
- 状态生命周期：unresolved → clarified / resolved / reinforced
- 支持多个专家对同一异常的交叉验证和状态更新
- 追问计数上限保护机制

### 2.9 最终报告生成

当策略监督器判定可以终止对话时，**报告生成器**汇总以下内容生成结构化报告：
- 综合 LieIndex 及各维度分数
- 各专家的关键证据摘要
- 未解决的异常点列表
- 整体风险评估和建议

报告以 JSON 格式保存到 `outputs/reports/`，同时输出详细执行日志到 `outputs/logs/`。

### 2.10 基准评测系统

`benchmark/` 目录提供了一套评测体系：
- **标注数据集**：`benchmark_annotation_template.csv` 包含真实/虚假样本的人工标注
- **评测指标**：准确率（Accuracy）、虚假样本召回率（Fake Recall）、虚假告警率（False Alarm）、风险分差（Risk Gap）
- **Baseline 对比**：`benchmark/baseline/` 提供不使用 Multi-Agent 流程的基础 Prompt 对比评测
- **Supabase 数据同步**：可从 Supabase 云端拉取原始评测数据

### 2.11 实时监控与日志

- **Agent 思考监控**：Web 界面和 CLI 均提供每轮各节点的执行摘要，可观察每个 Agent 的思考过程
- **详细日志**：每个节点的输入状态、输出更新、执行耗时、错误信息均记录
- **会话存档**：每次完整对话保存为带时间戳的 JSON 报告文件
- **可选的 Supabase 同步**：报告可自动上传到 Supabase 云端存储

## 三、配置系统

系统通过 `.env` 文件或 Streamlit Cloud Secrets 进行配置：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| DEEPSEEK_API_KEY | - | DeepSeek API 密钥 |
| DEEPSEEK_BASE_URL | `https://api.deepseek.com` | API 端点 |
| MODEL_NAME | `deepseek-chat` | 模型名称 |
| MAX_ROUNDS | 8 | 最大对话轮次 |
| MIN_FOLLOWUP_ROUNDS | 5 | 最少追问轮次（低于此值不会生成报告） |
| TEMPERATURE | 0.2 | LLM 温度参数 |
| SUPABASE_URL | - | Supabase 实例 URL（可选） |
| SUPABASE_SERVICE_ROLE_KEY | - | Supabase Service Role Key（可选）|

此外，系统启动时自动禁用 HTTP 代理（设置 `NO_PROXY=*`），确保 API 调用不被本地代理干扰。

## 四、系统边界与局限

1. **相亲场景特化**：追问策略、对话包装方式均针对中文相亲交友场景设计，泛化到其他场景需调整 Prompts
2. **LLM 依赖**：所有分析能力完全依赖底层 LLM（DeepSeek V3），分析质量受限于模型能力；JSON 输出格式不稳定时系统有重试机制但仍有失败可能
3. **软信号定性**：心理语言学分析仅为辅助参考，不能作为高风险判定的独立依据
4. **无实时联网**：职业常识分析依赖 LLM 训练数据中的知识，无法实时查询最新行业信息
